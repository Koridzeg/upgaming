# AI-ის გამოყენების ანგარიში

[English](ai-usage-report.md) · ქართული

ეს პროექტი ორი AI ინსტრუმენტის დახმარებით შევქმენი. კოდის, ტესტებისა და დოკუმენტაციის
უმეტესი ნაწილი **Claude Code**-მა დაწერა. **ChatGPT Astra** ჩემთვის მეორე აზრი იყო: მას ამ
კოდის განსახილველად და მის უკან მდგომი კონცეფციების გასაგებად ვიყენებდი. გადაწყვეტილებები მე
მივიღე. ყველა ანგარიში შევქმენი და ყველა საიდუმლო მონაცემი თავად დავაყენე, ყოველი ნაბიჯი
განვიხილე და დავტესტე, და ყველა commit თავად გავაკეთე. მთელ ნამუშევარზე პასუხისმგებელი მე ვარ
და ნებისმიერი ნაწილის ახსნა და შეცვლა AI-ის დახმარების გარეშე შემიძლია.

| ინსტრუმენტი | რისთვის ვიყენებდი |
| --- | --- |
| Claude Code (Anthropic-ის კოდირების აგენტი, VS Code-ში, Claude Opus მოდელით) | დიზაინის ვარიანტები, კოდი, ტესტები, ექსპერიმენტები, დებაგინგი, დოკუმენტაციის მონახაზები |
| ChatGPT Astra | Claude Code-ის დაწერილი კოდის განხილვა; კონცეფციების გაგება (RAG, Embeddings, რანჟირება, დიზაინის გადაწყვეტილებები) |

## როგორ იყო ორგანიზებული სამუშაო

ასისტენტს ცალსახად არ მივეცი ნება, რომ აპლიკაცია ერთბაშად შეექმნა. პროექტი 15 ნაბიჯად
(0-დან 14-მდე) აიწყო და ყოველი ნაბიჯი ერთსა და იმავე ციკლს მიჰყვებოდა:

1. **დაგეგმვა.** ასისტენტი მთავაზობდა დიზაინს ალტერნატივებით და მათი დადებითი და უარყოფითი
   მხარეებით; არჩევანს მე ვაკეთებდი.
2. **ჯერ ტესტები.** ქცევის ცვლილებისას ჯერ ტესტი იწერებოდა და გასწორებამდე მისი ჩავარდნა მოწმდებოდა.
3. **კოდი.** კოდს ასისტენტი წერდა; ტესტები და ლინტერის შემოწმება წარმატებით უნდა გასულიყო.
4. **განხილვა და ტესტირება.** კოდს ვკითხულობდი, მეორე აზრისთვის ChatGPT Astra-ს ვთხოვდი მის
   განხილვას, ვუშვებდი ტესტებს და ფუნქციონალს თავად ვცდიდი: ტერმინალში, API-ის მეშვეობით,
   UI-ში და მოქმედ Deployment-ზე.
5. **ახსნა.** ყოველი ნაბიჯის მსჯელობა, გაზომვები და გასაუბრების კითხვები სამუშაო ჩანაწერების
   დოკუმენტში იწერებოდა, რომ ყველა გადაწყვეტილების დაცვა შემძლებოდა.
6. **Commit.** ყოველი ნაბიჯის commit-სა და push-ს თავად ვაკეთებდი.

**საიდუმლო მონაცემების წესი.** API გასაღებები და მონაცემთა ბაზის URL-ები მხოლოდ ჩემს `.env`-ში
და Render-ის პარამეტრებში ინახებოდა. ასისტენტის სკრიპტები მხოლოდ იმას ბეჭდავდა, დაყენებული
იყო თუ არა გასაღები და რა სიგრძის იყო. თავად მნიშვნელობას არასდროს ბეჭდავდა.

## რა გავაკეთე მე

- **გადაწყვეტილებები:**
  - Angular UI-სთვის (ჩემი მთავარი სტეკი).
  - მხოლოდ უფასო ტარიფები, რის გამოც პასუხების უფრო მცირე შეფასებას დავთანხმდი.
  - Groq და Gemini, როგორც LLM პროვაიდერები.
  - PostgreSQL pgvector-ით, პროდაქშენში Neon-ზე.
  - Render, მას შემდეგ რაც აღმოჩნდა, რომ Hugging Face Docker Spaces ფასიან ტარიფს მოითხოვს.
  - ყველა ბონუს ფუნქციის რეალიზება.
  - თავად ნაბიჯ-ნაბიჯ მუშაობის მეთოდი.
- **ანგარიშები და საიდუმლო მონაცემები:**
  - შევქმენი Neon-ის, Render-ის, Groq-ის, Gemini-ისა და Hugging Face-ის ანგარიშები და API გასაღებები;
  - მივუთითე მონაცემთა ბაზის URL;
  - Render-ზე პროდაქშენის გარემო დავაკონფიგურირე.
- **განხილვა და ტესტირება:**
  - ყოველი ნაბიჯის კოდი და ახსნა წავიკითხე, ChatGPT Astra კი მეორე შემმოწმებლად გამოვიყენე;
  - Astra-ს დახმარებით დავრწმუნდი, რომ კონცეფციებიც მესმოდა და არა მხოლოდ კოდი;
  - ტესტების ნაკრები გავუშვი;
  - API, UI და მოქმედი დემო ხელით დავტესტე.
- **გასწორებები პროდაქშენში:** Render-ზე ვიპოვე და გავასწორე არასწორად დაკონფიგურირებული
  `DATABASE_URL`, რამაც პირველი Deployment შეაჩერა.
- **ისტორია:** რეპოზიტორიაში ყველა commit ჩემია.

## სად შეცდა Claude Code

განმავლობაში გამოვლინდა, და ისიც, თუ რამ გამოავლინა თითოეული.

## როგორ შემოწმდა სისწორე

- **ტესტები რეალურ ინფრასტრუქტურაზე:** 164 ტესტი რეალურ Postgres მონაცემთა ბაზაზე ეშვება.
  ჩანაცვლებულია მხოლოდ Embeddings-ის მოდელი და LLM, შესაბამისად იმიტაციით და სკრიპტირებული
  მოდელით. ეს აპლიკაციაში გაშვებული კოდის 93%-ს ფარავს.
- **გაზომვები ვარაუდების ნაცვლად:** მოძიებისა და პასუხების ხარისხი კითხვების ფიქსირებულ
  ნაკრებებზე, სანდოობის ინტერვალებით იზომება. დოკუმენტაციაში მოყვანილი რიცხვები ამ
  გაშვებებიდან არის აღებული.
- **შემოწმება რეალურ გარემოში:** ყოველი ნაბიჯი გამოიცადა რეალურ, 66,569 დოკუმენტიან მონაცემთა
  ბაზასა და რეალურ LLM-ებზე, Deployment კი მის საჯარო URL-ზე თავიდან ბოლომდე შემოწმდა.

## AI თავად პროდუქტში

შემუშავების ინსტრუმენტისგან დამოუკიდებლად, LLM-ებს თავად პროდუქტიც იყენებს:

- გამოძიების აგენტი (Groq-ისა და Gemini-ის მოდელების ჯაჭვი);
- ვერიფიკატორი, რომელიც წყაროს მითითებით გამყარებულ ყოველ მტკიცებას ამოწმებს;
- შეფასებისას, შემფასებელი მოდელი, რომელიც პასუხებს აფასებს. ის ყოველთვის განსხვავდება
  შესაფასებელი მოდელისგან.
